# Evidências

## 1. Objetivo

Esta pasta organiza as evidências relacionadas ao projeto **Documentação Técnica de um Copiloto com Fluxo de Conversa Personalizado**.

O objetivo é diferenciar claramente materiais que comprovam uma atividade realizada de materiais meramente ilustrativos, conceituais ou planejados.

---

## 2. Situação atual

No momento, **não existem evidências funcionais de uma implementação no Microsoft Copilot Studio** neste repositório.

A autora não possui acesso ao ambiente original utilizado para a implementação do cenário apresentado no desafio.

Por esse motivo, não serão criadas ou apresentadas capturas de tela simuladas como se fossem evidências reais.

---

## 3. Classificação das evidências

| Categoria | Descrição | Situação |
|---|---|---|
| Evidência funcional | Demonstra uma funcionalidade efetivamente executada | Não disponível |
| Evidência visual | Captura de tela de uma execução ou configuração real | Não disponível |
| Evidência documental | Documento, especificação ou registro que sustenta uma afirmação | Disponível no repositório |
| Evidência conceitual | Diagrama ou modelo produzido para representar uma proposta | Disponível/planejada |
| Evidência de processo | Registro do uso de IA, prompts e decisões de elaboração | Disponível |

---

## 4. Evidências documentais disponíveis

O próprio repositório contém registros documentais do processo de elaboração:

- metodologia utilizada;
- arquitetura conceitual;
- fluxo conversacional;
- requisitos;
- casos de teste planejados;
- prompts utilizados;
- análise crítica e limitações registradas nos documentos.

Esses materiais demonstram o processo de documentação, mas **não comprovam a execução de um agente funcional**.

---

## 5. Evidências visuais

### Situação atual

Não há capturas de tela reais do Microsoft Copilot Studio disponíveis.

Não é adequado utilizar imagens encontradas na internet como se fossem evidências da configuração deste projeto.

Imagens de documentação oficial podem ser utilizadas futuramente apenas como material de referência, devidamente identificadas como tal, e não como evidência de implementação própria.

---

## 6. Evidências dos testes

Os casos CT-01 a CT-08 documentados em `docs/05-testes/` são **testes planejados**.

Eles ainda não possuem:

- data de execução;
- ambiente de execução;
- resposta observada;
- resultado aprovado/reprovado;
- captura de tela da execução.

Portanto, não devem ser apresentados como testes realizados.

---

## 7. Evidências futuras

Caso o acesso ao Microsoft Copilot Studio seja obtido posteriormente, recomenda-se registrar, para cada evidência:

1. identificação do recurso demonstrado;
2. data da captura;
3. contexto da configuração ou teste;
4. captura de tela original;
5. relação com requisito ou caso de teste;
6. observação sobre o resultado;
7. nome do arquivo e localização no repositório.

Exemplo de nomenclatura:

```text
EV-001-configuracao-agente.png
EV-002-fluxo-duvidas.png
EV-003-fluxo-suporte.png
EV-004-fluxo-informacoes.png
EV-005-teste-saudacao.png
EV-006-teste-fallback.png
```

Os nomes acima são apenas um padrão sugerido e **não representam arquivos existentes atualmente**.

---

## 9. Integridade das evidências

Uma evidência somente deve ser apresentada como comprovação quando houver relação clara entre o material e a atividade alegada.

Não serão considerados evidências válidas:

- imagens inventadas;
- capturas simuladas apresentadas como reais;
- resultados de testes não executados;
- imagens genéricas de terceiros apresentadas como configuração própria;
- afirmações sem fonte ou registro correspondente.

---

## 10. Limitação documental

A ausência de acesso ao ambiente do Copilot Studio limita a produção de evidências funcionais e visuais específicas da plataforma.

Essa limitação é registrada explicitamente para preservar a transparência do projeto.

O projeto continua válido como **documentação técnica conceitual produzida com apoio de Inteligência Artificial**, mas não deve ser apresentado como comprovação de uma implementação funcional que não foi realizada.

---

## 11. Próxima etapa para obtenção de evidências

Se houver acesso ao Microsoft Copilot Studio no futuro, a documentação poderá ser complementada com evidências reais de:

- criação do agente;
- configuração dos tópicos;
- definição dos gatilhos;
- fluxo de atendimento;
- tratamento de entradas fora do escopo;
- testes;
- publicação, quando aplicável.

Cada nova evidência deverá ser vinculada ao requisito ou teste correspondente.

---

## 12. Observação

Esta pasta foi estruturada para manter a distinção entre **evidência**, **documentação**, **proposta conceitual** e **resultado de teste**.

Essa separação evita que conteúdo ilustrativo ou gerado por Inteligência Artificial seja interpretado como comprovação de execução.
