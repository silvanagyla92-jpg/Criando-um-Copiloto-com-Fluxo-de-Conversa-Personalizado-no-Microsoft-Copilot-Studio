# Evidências

## 1. Objetivo

Esta pasta organiza as evidências relacionadas ao projeto **Documentação Técnica de um Copiloto com Fluxo de Conversa Personalizado**.

O objetivo é diferenciar materiais que comprovam uma atividade realizada de materiais conceituais, documentais ou planejados.

---

## 2. Classificação das evidências

| Categoria | Descrição | Situação |
|---|---|---|
| Evidência funcional | Demonstra uma funcionalidade efetivamente executada | Não disponível |
| Evidência documental | Documento, especificação ou registro que sustenta uma afirmação | Disponível no repositório |
| Evidência conceitual | Diagrama ou modelo produzido para representar uma proposta | Disponível/planejada |
| Evidência de processo | Registro do uso de IA, prompts e decisões de elaboração | Disponível |

---

## 3. Evidências documentais disponíveis

O próprio repositório contém registros documentais do processo de elaboração:

- metodologia utilizada;
- arquitetura conceitual;
- fluxo conversacional;
- requisitos;
- casos de teste planejados;
- prompts utilizados;
- referências técnicas;
- análise crítica e decisões de elaboração.

Esses materiais demonstram o processo de documentação.

---

## 4. Evidências dos testes

Os casos CT-01 a CT-08 documentados em `docs/06-testes/` são **testes planejados**.

Eles descrevem entradas e resultados esperados para uma futura validação do fluxo conversacional.

---

## 5. Evidências futuras

Quando novos artefatos de projeto forem produzidos, recomenda-se registrar:

1. identificação do artefato;
2. contexto;
3. relação com requisito ou caso de teste;
4. observação sobre o resultado;
5. nome do arquivo e localização no repositório.

Exemplo de nomenclatura para artefatos:

```text
EV-001-arquitetura.png
EV-002-fluxo-conversacional.png
EV-003-requisitos.md
EV-004-casos-de-teste.md
```

Os nomes acima são apenas um padrão sugerido.

|---|---|---|
| Definição do cenário | Documentação do projeto | Disponível |

---

## 7. Integridade das evidências

Uma evidência somente deve ser apresentada como comprovação quando houver relação clara entre o material e a atividade alegada.

Não serão considerados evidências válidas:

- imagens inventadas;
- resultados de testes não executados;
- materiais de terceiros apresentados como produção própria;
- afirmações sem fonte ou registro correspondente.

---

## 8. Observação

Esta pasta mantém a distinção entre **evidência**, **documentação**, **proposta conceitual** e **resultado de teste**.

Essa separação ajuda a preservar a rastreabilidade e a confiabilidade dos artefatos do projeto.
